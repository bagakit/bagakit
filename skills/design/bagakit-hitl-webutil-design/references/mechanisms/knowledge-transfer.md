# Knowledge Transfer

## Owns

- Structure the page so the human can absorb and reconstruct the key model.
- Use chunking, anchors, examples, and media only when they improve recall.
- Present problem-generated relationships between prerequisites, constraints,
  failure modes, and applications when the source provides them.

## Does Not Own

- Overall page skin, pane layout, or scene-specific chrome.
- Learning diagnostics, mastery claims, transfer policy, or retention evidence.

## Design Checks

- Core claims are grouped and sequenced.
- The page exposes what matters now versus supporting detail.
- Child nodes explain which parent problem or constraint generated them.
- When a mastery-learning handoff exists, the page preserves its objective and
  evidence boundaries without redefining them.

## Outputs Or Evidence

- A restatable model, checklist, or summary packet the human can return.
- For course pages, a visible next action and evidence context supplied by the
  upstream course contract.

## Failure Signals

- The page is dense but not learnable.
- Key ideas are present yet hard to reconstruct from memory.
- A decorative topic tree has no problem-generated edges.
- Page progress is presented as mastery.
