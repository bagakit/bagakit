# Artifact Lenses

Read only the lens that can change the current review. Every observation must
map back to `meaning`, `structure`, `choice`, `coupling`, or `proof` in the
stable review contract.

## Skill

Bind the host and loading model before estimating context burden.

Inspect:

- discovery load: whether name and description discriminate the trigger and
  exclusions
- activation load: decision-bearing obligations always loaded from `SKILL.md`
- conditional load: references, scripts, examples, or assets read only for an
  activated route
- route overlap: modes whose choice does not change behavior
- dependency depth: rules that require several other rules or resources to
  become usable
- authority conflict: same-level instructions that resolve the same action
  differently
- payload leakage: maintainer-only material shipped in the install unit
- validation selection: risk-triggered proof versus always-run ceremony

Candidate transformations:

- keep trigger, scope, protected boundary, common route, and stop condition on
  the loaded path
- move conditional detail one discoverable hop away
- replace repeated deterministic mechanics with an owned script
- consolidate duplicated truth at its owner
- combine cohesive routes when separation would duplicate context or handoffs

Do not infer entropy from `SKILL.md` line count or resource count. A long skill
can be regular and necessary; a short skill can be ambiguous or unsafe.

## Project

Choose one bounded user or maintainer task rather than reviewing the entire
repository abstractly.

Inspect:

- durable states, owners, APIs, abstractions, and control planes
- duplicated truth and compatibility-only paths
- direct and transitive change propagation for one representative commitment
- fragmented or mixed ownership boundaries
- route, configuration, exception, retry, and fallback growth
- validation propositions, error modes, selection scope, and retirement state
- unfinished migrations and scaffolding

Counts and graph measures are comparable only under the same partition and
extraction method. A monolith can game coupling counts; excessive splitting
can reduce local scores while increasing navigation and handoffs.

Protect domain behavior, public contracts, authority, recovery, endpoint
correctness, and independent proof. Prefer the smallest owner-local change
whose public behavior can be verified.

## Article Or Document

Bind the reader, task, prior knowledge, stakes, evidence duties, and genre.

Inspect:

- model discontinuity: missing relations, unstable terms, ambiguous referents
- signal mismatch: headings or summaries that predict the wrong content
- nonfunctional reprocessing: repeated propositions with no new function,
  audience state, evidence value, retrieval value, or risk protection
- integration burden: distant unresolved dependencies and representation
  switching
- weak information scent: labels that force scanning and backtracking
- premature disclosure: rare detail interrupting the common path
- reader mismatch: over-explanation for experts or missing support for novices

Valid reductions include deleting, merging, moving, or deferring. Valid
increases include adding one bridge, local definition, warning, or navigation
cue when it removes more reader work than it adds.

Do not replace this lens with readability, word count, lexical density, or
section count. Repetition can protect learning, accessibility, retrieval,
independent evidence, or safety.

## Validation Stack

Map every item as `check -> evidence -> decision`.

Ask:

- which failure and consequence it protects
- which owner or authority consumes the result
- which result changes accept, reject, revise, escalate, or continue
- whether another proof covers the same proposition through the same error
  route
- execution, triage, delay, false-positive, rework, maintenance, and side-effect
  cost
- stop and reopen conditions

Preserve mandatory boundary proof and independent evidence. Demote useful but
non-blocking diagnostics. Consolidate correlated checks with no possible
decision delta. Escalate when the risk owner or authority is missing.

## Protected Countercases

Before recommending reduction, test only triggered countercases:

- requisite variety: different environmental states require different actions
- change containment: a boundary localizes a volatile decision
- endpoint correctness: component proof does not entail user-visible acceptance
- layered defense: different mechanisms detect, contain, or recover from
  different failures
- reliability redundancy: evidence routes are meaningfully independent
- observability: a signal distinguishes consequential hidden states in time
- expert precision: qualifiers or repeated terminology change truth,
  obligation, interoperability, or harm
- audience support: repetition or disclosure serves a materially different
  reader state

When the domain model or qualified owner is missing, use `abstain` or `review`.
Do not run every countercase as a ritual.
